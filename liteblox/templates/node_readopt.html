Re-adopt nodes

When LiteBlox's data is lost (the container's volume, say) but its nodes keep running, a new LiteBlox can rebuild what it knew from them: every key with its secret, the ACLs, each node's server settings, the zones with their grants and contents, the primary and its secondaries, on DHCP nodes the subnets, reservations, the failover pair and where clients are registered in DNS, and on time nodes the time sources. Nodes without BIND come back from their Kea and chrony config alone. It goes ahead only when rendering the config back from the rebuilt data gives every node's files byte for byte, so nothing on the nodes changes. The one exception is a DHCP failover pair, which gets new certificates from this LiteBlox's CA. How it works

Not recovered: users (beyond the ones made here), the audit log, each zone's history before now, drafts, LiteBlox's list of backups, and comments on DHCP subnets and reservations, and IPAM (networks, ranges, IPAM records). Restoring a backup of the data volume keeps all of that, so prefer it when you have one.
