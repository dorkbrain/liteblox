Quick reference

Ports

Plain HTTP on 53530, always. HTTPS on {{ port }} while it's on. Publish both in your compose file.

Files

In ./data/tls/: cert.pem (the certificate, then its chain) and key.pem (the key, without a password). Written from the host, they must be readable by uid 1000.

Live updates

LiteBlox looks at the files every few seconds. A new pair goes to new connections within about 5 seconds, with no restart. A pair that doesn't load (a key that doesn't match, a renewal caught halfway) is ignored, and the old one keeps serving. Status and the Dashboard say why.

Renewing outside LiteBlox

Point certbot or acme.sh at ./data/tls/ (a deploy hook that copies the key, then the certificate): an example in Help.

From the container

liteblox https status
liteblox https allow-http
liteblox https off
liteblox https on
liteblox https regenerate --name NAME

Run each as docker compose exec liteblox liteblox https ….

Logins

A login is per scheme: logged in over HTTP, you log in once more over HTTPS.
